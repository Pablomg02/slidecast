# 0001 — syncdeck v1: synced HTML presentation server

## Justification

The author builds class presentations as single-file HTML decks generated with
AI. Opening such a file in a browser gives one window and nothing else: no
presenter view with notes and the next slide, no way to drive the projector
from a phone, no way for students to follow on their own laptops, and no place
to keep speaker notes outside the HTML. PowerPoint's presenter/audience split
is what is missing, plus remote access through the author's Raspberry Pi
(e.g. `slides.pablomagarinos.es`).

Real scenarios that must work:

1. **Class, one laptop.** `syncdeck serve` locally; one tab in presenter mode,
   another tab (on the projector screen) in viewer mode. No password setup.
2. **Phone as remote.** Server on the Pi behind Cloudflare Tunnel; the phone
   opens presenter mode (password), the classroom PC opens viewer mode.
3. **Students follow along.** Students open the public URL and join as viewers.
4. **New deck from anywhere.** Admin logs in on the Pi's URL, uploads a deck,
   writes the speaker notes in the browser; they are saved to the deck's JSON.

### Goals

- A Node.js server that serves every deck in a data folder, each deck being a
  folder with `index.html` (+ optional `deck.json` and assets).
- Three roles: viewer, presenter (password), admin (hidden `/admin`, password).
- Presenter and viewers stay in sync over WebSocket; the protocol carries
  typed commands so new ones (text overlay, pointer…) can be added later.
- Steps are discrete: the deck only moves when someone presses next/prev
  (arrows, space, PageUp/PageDown from a clicker, on-screen buttons, swipe).
- Viewer navigation policy per deck: `follow` (locked), `back` (may go back,
  never past the live step), `free` (anywhere), switchable live by the presenter.
- Presenter view: current step, next step preview, notes, timer, clock,
  counter, blank screen, connected viewers; usable on a phone.
- Admin panel: upload (zip or html), delete, featured deck, public listing
  toggle, passwords, per-deck settings, notes editor that writes `deck.json`.
- Root redirect rules exactly as specified (D7).
- Works with the author's existing decks (legacy `PRES` engine) and with a
  documented native deck API for future decks.
- Safe to expose on the Internet from a public repository: secure sessions,
  hashed passwords, no secrets in git, decks sandboxed.
- Deployment recipe for Raspberry Pi with Cloudflare Tunnel.

### Non-goals

- v2 features: QR code to join, text overlay, laser pointer, audience
  questions/reactions, PDF export. The protocol must allow them, nothing more.
- Syncing state *inside* a step (interactive simulations, videos, scroll).
- Editing the deck HTML itself in the browser (the author edits with AI).
- Multi-user admin accounts or roles beyond the three above.
- A generic engine for arbitrary HTML that implements neither adapter (D5).
- Updating the author's private deck template (separate
  follow-up in that repository).
- reveal.js compatibility.

### Approach

**Architecture.** One Node process (Fastify) serves HTML pages, a JSON API,
static UI assets, deck files and a WebSocket endpoint per deck. The server is
the single source of truth for each deck's live state (`index`, `blank`,
`viewerNav`). Clients render; presenters send commands; the server validates
the sender's role and broadcasts the new state.

**Shell + sandboxed deck.** Every UI page (viewer, presenter, editor) is a
"shell" page from syncdeck that embeds the deck in an `<iframe sandbox="allow-scripts">`
(no `allow-same-origin`). The deck therefore runs on an opaque origin: it
cannot read syncdeck's cookies or call its API, so a deck generated by AI or
downloaded cannot act as the admin. When the server returns a deck's
`index.html` it injects `<script src="/_syncdeck/bridge.js"></script>` as the
first child of `<head>`. The bridge talks to the shell with `postMessage`,
finds the deck's navigation API (native or legacy `PRES`), reports steps and
changes, executes `go`, and captures navigation input (keys, clicks, swipes)
in the capture phase so the deck never moves on its own: it forwards the
intent to the shell, which applies the role's policy.

Deck files are served under a path that carries an access token
(`/_deck/<slug>/<token>/…`). Cookies are not reliably sent by an opaque-origin
document, so the token is what authorises the iframe and its relative assets.

**Discarded alternatives.** Injecting the WebSocket client into the deck itself
(simpler, but gives deck code same-origin access to sessions); reveal.js and
its multiplex plugin (the author wants a tool of their own and their decks
already have an engine); SSE + POST (fine, but WebSocket is simpler for
bidirectional commands and works through Cloudflare Tunnel); a frontend build
step (decks and UI are edited by AI; plain ES modules are easier).

### Interfaces fixed by this plan

**Bridge ↔ shell (`postMessage`, every message has `sd: 1`).** The shell
accepts a message only if `event.source === iframe.contentWindow`; the bridge
accepts only from `window.parent`. Target origin `"*"` (the iframe origin is
opaque), so messages never carry secrets.

| Direction | Message |
| --- | --- |
| bridge → shell | `{t:"ready", adapter:"native"\|"legacy", steps:[{slide, step}], index}` |
| bridge → shell | `{t:"changed", index}` (after any change, including ones the shell requested) |
| bridge → shell | `{t:"input", action:"next"\|"prev"\|"first"\|"last"\|"blank"\|"fullscreen"\|"live"}` |
| bridge → shell | `{t:"error", code:"no-deck-api"}` |
| shell → bridge | `{t:"go", index}` |
| shell → bridge | `{t:"mode", mode:"live"\|"preview"}` — `preview`: all input ignored, media muted and paused |

**Native deck API** (for new decks; documented in `docs/deck-format.md`):

```js
window.SYNCDECK_DECK = {
  version: 1,
  steps: [{ slide: "intro", step: 0 }, { slide: "intro", step: 1 }],
  go(index) {},          // jump to step index, no animation required
  current() { return 0; },
};
// after every change:
window.dispatchEvent(new CustomEvent("syncdeck:change", { detail: { index } }));
// When embedded, the bridge sets window.__SYNCDECK__ = { embedded: true } before
// any deck script runs; the deck then must not bind its own navigation input.
```

**WebSocket protocol** — see T6. **HTTP routes** — see T7, T8, T11.

#### T6 — Live hub (WebSocket)

- **Objective:** per-deck live state with role-checked commands and broadcasts.
- **Files:** `src/live.js`, `test/live.test.js`.
- **Depends on:** T2, T3 (uses `auth` from T7 through an injected `authorize(req, slug, role)` function, stubbed in tests until T7)
- **Details:** Route `GET /ws/:slug` (WebSocket). Upgrade checks: deck exists; Origin per D12; `role=presenter` requires `canPresent`, `role=viewer` requires `canView`; failure → close code `4401` (unauthorized) or `4404` (no deck). State per deck: `{index, total, blank, viewerNav, rev}`; `viewerNav` initialised from `deck.json`; `index`/`blank` restored from `live.json` (D25). Messages:
  - server → client: `{t:"state", index, total, blank, viewerNav, rev, presenters, viewers}` on connect and after every change or connect/disconnect; `{t:"notes", slides}` to presenters when notes change (T11); `{t:"error", code}`.
  - presenter → server: `{t:"meta", total}` (from the bridge's `ready`; server keeps the max reported); `{t:"step", delta: 1|-1}`; `{t:"goto", index}`; `{t:"blank", on}`; `{t:"nav", mode}`.
  - `index` is clamped to `[0, total-1]` when `total` is known. Viewer-originated commands → `{t:"error", code:"forbidden"}`, state unchanged. Invalid JSON or unknown `t` → `error bad-message`; messages > 4 KB → close `1009`. `rev` increments on each change. Heartbeat per D2.
  - Export `notifyNotes(slug, slides)` and `getState(slug)` for other modules.
- **Acceptance criteria:**
  - [ ] Tests with real `ws` clients on a listening server (port 0): presenter `step +1` → both viewer and presenter receive `state` with `index 1`; viewer `step` → `error forbidden`; `goto 999` with `total 10` → `index 9`; two presenters each send `step +1` → `index 2`; upgrade with a foreign `Origin` → rejected; state survives a server restart via `live.json`.

### Risks

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Sandboxed opaque-origin iframes behave differently across browsers (fullscreen, media autoplay, `history.replaceState`). | Legacy adapter or fullscreen breaks on some browser. | T5 is early and e2e-tested; fullscreen is requested by the shell on its own document, not by the deck. Manual check in Firefox and Safari/iOS during verification. |
| Legacy click heuristic swallows a click meant for interactive deck content. | A button inside a slide stops working. | Interactive elements and `[data-interactive]` pass through; documented. |
| Two copies of a heavy deck (current + next) in the presenter page. | Slow presenter page on a phone. | Next preview is not created on the phone layout; the desktop next preview loads with `?static`. Otherwise accepted for v1. |
| Cloudflare closes idle WebSockets. | Silent desync. | Ping every 25 s, client reconnect with full `state` on reconnect. |
| Admin forgets to set passwords before exposing the Pi. | Anyone could present/admin. | D10 refuses password-less access through proxies; CLI warns on non-loopback bind without passwords; deploy doc sets passwords first. |
| Upload of a malicious zip. | Files written outside the data dir or disk filled. | D20 validation, tests in T3. |

Deviations:
- T1: `npm test` is `node --test test/*.test.js`, not `node --test test/`: on Node 22 a directory argument is loaded as a module and fails ("Cannot find module …/test"). The shell expands the glob, so it also works on Node 20.
- T3: zip reading lives in `src/unzip.js` (own central-directory parser + `zlib.inflateRawSync` with `maxOutputLength`), because fflate exposes neither the external attributes needed to detect symlink entries nor an output cap per entry. fflate is still used to build zips in tests. `__MACOSX/` entries are skipped so zips made by macOS Finder work.
- T4: the sandbox CSP and `Referrer-Policy: no-referrer` are sent on every `/_deck/` response, not only `index.html`: otherwise an `.html` or `.svg` file inside a deck, opened directly, would run on syncdeck's origin. Only the root `deck.json` is hidden.
- T6: an Origin mismatch rejects the upgrade with HTTP 403 (before the WebSocket exists); 4401/4404 are used once the socket is open. A presenter's permission is re-checked on every command, so revoking a session stops an open socket from driving the deck. Added `resetDeck(slug)` for T11 (re-upload forgets the step count; delete closes sockets with 4404). `npm test` also gets `--test-timeout=30000` so a hang fails instead of blocking.
- T7 (clarifications of D9–D11, no behaviour asked for is dropped): a `"*"` session (global presenter password) does not cover a deck that has its own presenter password, because D9 says the deck password overrides the global one. Changing the global presenter password also revokes deck grants obtained through it. `canView` is true for anyone who `canPresent`. Login keeps the scopes of the previous session in the new one (new id each time). Rate limiting uses two `createRateLimit` limiters in one preHandler (the plugin's `rateLimit()` handler runs only once per request). The server watches `config.json` (every 2 s) so `syncdeck passwd` takes effect, and revokes sessions, while it runs. Fastify's `text/plain` parser is removed (cross-site forms can send it).
- T8: D7's "admin session" is read as a logged-in admin session; a local-direct request without an admin password (which may use `/admin`) still gets the redirects. This is what T13's criterion (`serve examples/demo` → `GET /` 302 `/demo`) requires. Added `src/paths.js`, a `notfound` page and `/robots.txt` (`Disallow: /`).
- T9: the shell tells its own `go` results apart from a deck that moved by itself (e.g. through its own index overlay): `onChanged(index, own)`; the viewer accepts a spontaneous move only if its mode allows it, otherwise sends the deck back. Mouse moves over the iframe never reach the shell, so cursor auto-hide uses a transparent cover that appears after 2.5 s idle and disappears on the first mouse move (a click on it counts as "next", like a click on the deck). Added `public/notfound.js`. Note for testing: a browser on the server machine with no admin password is the implicit admin (D10), so it can present; e2e specs that need a plain viewer set both passwords.
